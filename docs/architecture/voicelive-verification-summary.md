## Architecture Verification

### Backend Connection (WebSocket Proxy)
- **Modalities**: `[TEXT, AUDIO]` only
- **Purpose**: Audio streaming and transcript persistence
- **Memory**: Transcripts persisted to Zep via backend

### Video Connection (Direct Browser)
- **Modalities**: `[VIDEO, TEXT]` (separate connection)
- **Purpose**: Avatar video streaming
- **Token**: Generated by backend, provided in `agent_switched` message
- **Connection**: Browser connects directly to Azure using token

## Expected Behavior

### When VoiceLive WebSocket Connects:

1. **Backend establishes connection** with `[TEXT, AUDIO]` modalities
2. **If avatar enabled** (Elena):
   - Backend generates video token
   - Sends `agent_switched` message with `video_connection`:
     ```json
     {
       "type": "agent_switched",
       "agent_id": "elena",
       "video_connection": {
         "token": "...",
         "endpoint": "wss://...",
         "modalities": ["video", "text"]
       }
     }
     ```
3. **Audio flows through backend**:
   - `RESPONSE_AUDIO_DELTA` events → forwarded to browser
   - Transcripts → persisted to Zep memory
4. **Video flows directly** (when frontend implements):
   - Browser uses token to connect directly to Azure
   - Video events handled in browser (not backend)
